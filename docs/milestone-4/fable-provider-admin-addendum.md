# M4 addendum: platform admin and provider connections

**Scope statement.** This adds a founder-only platform admin surface over the existing M4 design. Nothing here changes sealed migrations, the formula, snapshots, or the two scoped roles already decided. Only the Bachs sandbox adapter ships. Nothing in this addendum makes an unknown provider connectable without code.

## Identity, MFA and the registry

- **Platform admin is a database fact, never a JWT claim or workspace role.** Add `platform.admins` keyed by auth user id with `granted_by`, `granted_at`, `environment` constrained to `sandbox`. Rows are inserted only by the database owner in a dev fixture. No RPC creates or edits them. Workspace Owner membership confers nothing here, and admin status confers no workspace membership. Admin RPCs never read or write workspace data beyond non-secret billing state.
- **MFA via Supabase TOTP, checked in SQL.** Every admin writer that stores, rotates, enables, disables or changes default reads `auth.jwt()->>'aal'` and fails `mfa_required` unless it is `aal2`. Reads of non-secret state need `aal1`. The Edge credential function repeats the same check before any Vault call.
- **Supported-provider registry.** `platform.providers` is seeded only by migration. One row: `bachs`, with `adapter_version`, fixed `sandbox_base_url`, `key_prefix='sk_sandbox_'`, `environment='sandbox'`, and a capability map listing USD recurring verified and NGN recurring unverified. The dashboard lists registry rows only. A provider absent from the registry cannot be connected, and the UI says so plainly rather than offering a form. No base URL, header or adapter field is admin-editable.

## Connections, credentials and pinning

- **Connection is the unit of everything.** `platform.provider_connections` holds `id`, `provider_code`, `label`, `status` in draft, tested, enabled, disabled, `credential_secret_id`, `credential_version`, `webhook_secret_id`, `expected_organization_id`, `last_test_id`, `accepting_new`, `version`. Enabled requires a passing test within the last day and `aal2`.
- **Write-only credential input, browser to Edge.** The admin page renders the form, but the secret field submits from the browser directly to the Edge function `platform-credentials` with the admin's JWT. Next server code never sees the value, so no payment secret ever enters Vercel and Preview protection stays untouched because the admin browser is already past it. The function checks admin row, `aal2`, key prefix and registry base URL, then calls one SQL function `platform.store_credential` which writes to Vault and records only `secret_id`, a short fingerprint, `stored_by` and `stored_at`. No path returns the value. A test asserts no table outside Vault contains a string matching the key prefix.
- **Narrow Vault grants.** Revoke everything on `vault` from `anon`, `authenticated` and all scoped roles. `platform.get_credential(connection_id)` and `platform.get_webhook_secret(connection_id)` are security definer, owned by postgres, fixed `search_path`, granted only as below. Nothing reads `vault.decrypted_secrets` directly.
- **Pinning and isolated identifiers.** Add `provider_connection_id` to `workspace_billing`, `checkout_intents`, `paid_periods`, `webhook_inbox`, `review_queue` and `worker_runs`. Every unique index on a provider identifier becomes composite with the connection id, so a reused Bachs id on a second connection can never collide with or bind to the first. The webhook route carries the connection id in its path, and signature lookup is by that id. Worker claims are per connection. The subscription's connection and the intent's pinned product, currency and amount are immutable for its lifetime, consistent with Sol's point ten.
- **Default affects new checkouts only.** `platform.settings.default_connection_id` is read inside `create_checkout_intent` at intent creation and pinned there. Renewals, portal, cancel and absorb always resolve credentials from the pinned connection, never from the default.

## Activation, disable, rotation, prices, topology

- **Sandbox-only activation test.** The "Test" button invokes Edge `platform-provider-test`, which makes read-only provider calls with the connection's credential: one authenticated GET to confirm the key works, a check that the returned organization matches `expected_organization_id`, and a product read for each configured price. It writes `platform.connection_tests` with outcome and redacted detail. Live keys are impossible by construction: the registry has no live environment row and the prefix check runs in SQL and Edge.
- **Disable means stop new business, not stop verification.** Disabling sets `accepting_new=false`, so checkout refuses `provider_unavailable`. Webhook intake, worker reads and absorb continue for pinned subscriptions. Deleting a credential is refused while any subscription or pending intent pins the connection. The UI states this before confirming.
- **Rotation keeps the old version until the new one is proven.** `rotate_credential` stores a new Vault secret, bumps `credential_version`, and marks it `pending` until a test passes, after which the worker switches and the old secret is scheduled for removal after one successful cron run. Webhook secret rotation keeps two active secrets for an overlap window, and the receiver tries both in constant time.
- **Admin audit without secrets.** `platform.admin_audit` records actor, action, connection id, credential version, fingerprint, `aal`, and before and after values of non-secret columns. Edge logs are redacted by a shared `redact.ts` that is unit tested against the key prefix.
- **Operator-configured prices.** `billing.plan_prices` is keyed by connection, plan and currency, with `provider_product_id`, `amount_minor` via `billing.to_minor`, `active`, `label`, `version`. Activation needs `aal2` and a product read confirming currency and amount match. NGN rows cannot activate until the database owner sets `ngn_recurring_verified_at` from real evidence. Both prices keep the "Sandbox proposal" label. This replaces the nullable columns on `billing.plans`; the plan row keeps limits only.
- **Topology.** Next reads non-secret admin state through user-scoped RPC `platform.admin_overview`. Non-secret writes such as default change and disable are RPCs with the `aal2` check. Anything touching a secret goes browser to Edge. Provider calls remain Edge-only. The admin dashboard is a protected route under the existing Next guard, and no Vercel protection bypass is introduced or needed.
- **Roles, resolved with the current two.** Keep `billing_intake` and `billing_worker` as decided. Grant `get_webhook_secret` to intake and `get_credential` to worker. Add `billing_caller`, used by checkout, portal and cancel functions, with execute on `get_credential` only, so user-facing functions never gain absorb or claim rights. Add `platform_admin` with execute on `store_credential` and `rotate_credential` only. Four roles total. If Sol wants fewer setup steps, fold caller into worker and record the widening explicitly. Supabase function secrets then hold only the worker token and role passwords, never a provider key, which removes one setup step from slice two.

**Minimum M4 implementation.** One forward migration adding the `platform` schema, connection and price tables, column additions and composite indexes, the Vault wrapper functions, the two new roles without passwords, and the dev admin fixture. Three Edge functions: `platform-credentials`, `platform-provider-test`, and the connection-aware changes to the existing receiver and worker. One Next admin area with registry list, connection detail, test, enable, disable, rotate, default selector, price editor and audit view, all in unconfigured state. Exactly one adapter, Bachs sandbox.

**Future provider integration work, stated honestly.** Each new provider requires a registry seed migration, a code adapter implementing the shared interface for customer, checkout, subscription, payment, refund, dispute, portal and webhook verification, contract tests against that provider's official schema, a real sandbox evidence run, and Sol-managed secrets. The dashboard then shows it. No provider becomes connectable through the dashboard alone.

**Required local tests, rolled back on real Postgres.** Admin without row and Owner without admin row are refused. `aal1` fails every writer. Non-registry provider code is rejected at the CHECK. Key with wrong prefix is refused in SQL. No non-Vault column holds a key-shaped string. Two connections with identical Bachs ids never collide or cross-bind. Default change leaves existing subscriptions and renewals on their pinned connection. Disable refuses checkout but absorb still grants a verified renewal. Rotation keeps the old version until test passes. Credential deletion is refused with active subscriptions. NGN price cannot activate unverified. Audit rows contain no secret. Grant sweep covers `platform` and `vault`.

**Required real sandbox evidence, labelled as such.** Credential stored through Edge and absent from Vercel logs. Test call succeeds and organization matches. Rotation with a second sandbox key with cron worker rows on the new version. Webhook received under a rotated secret. Default switched between two sandbox connections and new checkout pinned to the new one while an existing subscription renews on the old. Live key refused.

# Sol binding implementation review

The Fable text above is preserved as received. These corrections take precedence:

- The existing scoped roles are billing_intake, billing_gateway and billing_worker. Reuse billing_gateway for checkout, portal and cancellation; do not add a duplicate billing_caller or collapse it into worker. Add a separately scoped credential-management runtime role only if required; SQL must independently verify the authenticated platform administrator and aal2. Role possession alone cannot authorize an operator action.
- Pin provider connection and credential/price versions on all applicable identifiers, including customers, subscriptions, invoices, payments, tombstones, failures and collision records. Scope customer uniqueness and provider identifier uniqueness per connection. Lock ordering must remain consistent with the core billing repair.
- billing.plan_prices already exists in the initial M4 draft; extend that design rather than assuming prices are nullable columns on billing.plans.
- USD recurring is supported by provider documentation, not yet verified on this sandbox account. A successful credential/product GET is not evidence that a subscription, renewal or webhook lifecycle works. NGN activation requires real account-specific recurring evidence.
- Vault permission changes must be limited to this implementation and must not revoke unrelated existing service permissions. No plaintext credentials in source, non-Vault tables, logs or returned RPC payloads. Test redaction and operation-specific grants.
- Credential retirement must wait for all in-flight uses and verified overlap requirements, not just an arbitrary first cron run. Preserve old webhook secrets through the defined retry overlap.
- Founder selected Paystack and Stripe alongside Bachs. Prepare the admin registry/interface to accommodate these supported integrations, but do not label either connected, tested or enabled before its adapter and sandbox checks exist. Bachs remains the first M4 sandbox implementation; unsupported or pending adapters must show a truthful unavailable state. No live activation is authorized.
