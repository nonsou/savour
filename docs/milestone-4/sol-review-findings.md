# Sol independent review findings — first local draft

Not a final verdict: Opus implementation is still in progress and has not been deployed.

1. Guest invitation creation takes the workspace billing row lock in require_capacity before inserting an invitation referencing the session. PostgreSQL FK validation takes FOR KEY SHARE on the session; existing evidence writers hold FOR UPDATE on the same session and may subsequently need billing. This creates a real reversed lock order. For guest create_invitation, acquire the live session evidence lock before any billing lock, revalidate collection and roster under it, and retain the established invitation/session/directory/member/billing order. Add a two-connection check for guest invitation creation vs opening/review/assignment on the same session.

2. The first draft gates many writers but leaves save_category, save_subject_contact, update_session_draft and existing directory edits ungated, while save_subject can change name/type/category/external ID/location associations after expiry. Inspect all public writer paths rather than only new table inserts. Strict read-only must reject new/edited directory, categories, contacts, drafts, scopes and templates; narrowly allow archive/revoke reductions without permitting unrelated edits bundled in an archive request. Keep accepted assessment correction, approval, existing action progress, security and reads/exports intact. Reopening collection needs explicit writable access even when all assignments have consumed reservations; it is distinct from reopening a report for correction.

3. Payment verification currently treats absent amount_paid and absent line_items as acceptable, and does not explicitly bind payment.customer to the intended customer. Check the real adapter contract before concluding: if unavailable provider fields require a different verified object, fetch it rather than guessing. At a minimum exact fully collected amount/customer/subscription/product/invoice binding must be demonstrated; null payment amount evidence cannot silently mean fully paid. Verify invoice/payment period identity against the subscription period where appropriate, permitting genuinely older paid renewal periods through an explicit rule rather than ignoring it.

4. consume_assessment inserts unreserved consumed work when no reservation exists. Require a genuinely previously accepted reservation or an explicit historical approved-report correction exception, not an unconditional escape hatch. Show that no new assignment/draft can create an initial submission after read-only and preserve previously accepted waived/released correction work under a documented rule.

Continue checking after implementation completes; do not change Opus-owned source concurrently.

5. Refund-before-payment race: absorb_refund with no paid period takes only the event fence and inserts a tombstone, while absorb_payment takes the workspace billing lock, reads tombstones, then inserts a period. Two different event rows do not serialize these operations; a concurrent verified payment can observe no tombstone while the refund observes no period, then both commit a valid period plus tombstone. Resolve both paths on a shared payment serialization lock in a consistent lock order (or derive the bound workspace from verified payment and lock it before checking); include dispute-before-payment where applicable. Demonstrate actual overlap and ensure the resulting paid period is revoked/ungranted.

6. Daily reconciliation currently returns current subscriptions and unresolved checkout IDs, not historical paid-payment IDs. Review the completed worker: it must reconcile recent verified payments for missed refund/dispute notifications, and dispatch re-read refunded payment statuses to absorb_refund even when absorb_payment would return duplicate. Do not mark reconciliation complete solely because subscription status was fetched.
