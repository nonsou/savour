## Product requirements preserved

- One Business plan monthly per workspace. Paid limits: 3 active locations, 100 active subjects, 10 persistent staff including owners, 1000 initial subject-assessment submissions per period. Guests are not staff seats but their assessments count. Archived subjects release active-subject slots. No overage charges. Frozen reports and exports do not count.
- Cardless 14-day SAVOUR trial starts on verified workspace creation. Trial limits 1 location, 20 subjects, 5 staff, 100 assessments. Show end time and workspace timezone; warn at 80%. Do not enable Bachs card-collecting trial: SAVOUR owns the trial and checkout buys paid service only on explicit consent.
- Trial expiry/read-only preserves existing records and authorized report/export access. Owner can manage/pay billing; don't block essential access revocation/security operations. At a quota, allow completion/correction/approval/export of accepted reserved work. Atomically reserve assessment capacity when opening/assigning a session and release unused at close; edits/retries never count twice. Database enforces all gates, not only UI. Document historical workspace/reservation backfill without pretending paid access exists. All 25 accepted report snapshots and nine applied migrations are sealed.
- Owner-only checkout, provider customer isolated per workspace even when same owner owns several businesses. Persist checkout intent (workspace, owner, selected server plan/product/currency/amount, reference) before provider call. Return processing until server-confirmed payment. Bind provider checkout/customer/subscription/invoice/payment to intended workspace; arbitrary metadata or email never sufficient. Check amount/currency/recurrence/product/period/status using server provider reads. Clear price, renewal, taxes/fees, cancellation/refund terms before consent. Final price is not approved: sandbox proposal conspicuously labelled and configurable; don't publish commercial price.
- Payment pending retains prior valid access. Active only for verified successful paid period. Failed initial payment does not grant access or grace. Previously paid failed renewal has 7-day grace, then read-only; owner recovery notices on days 0, 3, 6 without duplicating provider charge retries. Cancel scheduled keeps access until paid-through, no extra renewal. Suspended is separately audited security policy. No deletion of reports on billing state change.
- Durable signed webhook inbox and retryable worker, duplicate-safe local payment ledger, no stale event overwriting later verified payment. Daily unresolved reconciliation; prove actual job path. Persist before acknowledge; crash/provider timeout/DB failure must remain retryable. Refund affects only associated paid period, partial refund/dispute flags review without destroying later entitlement. Cancellation provider-confirmed vs pending accurately shown. Owner-only fresh portal URL/invoices; never store/log short-lived portal credentials. No provider billing email broadcast or live scheduler changes without explicit scope.
- No annual billing, proration, coupons, upgrades, second provider, connected accounts, vendors' payouts, FX conversion or automatic overage. Current milestone sells SAVOUR workspace access only.

## Bachs integration contract discovered

Official API index: /tmp/savour-m4-bachs-index.txt . Use https://sandbox-api.bachs.io. API money uses decimal strings at currency precision, unlike Paddle minor units; internal ledger may use exact integer minor units with explicit conversion. No floating-point multiplication or unverified mixed-currency revenue.
Recurring subscriptions originate via POST /v1/checkout-sessions with product_cart quantity=1 for recurring product, billing_currency and success/cancel URLs. No POST subscriptions. Customer portal POST /v1/customers/{customer_id}/portal-sessions has no body and needs customers:write; response URL is a secret, mint only on owner request.
Webhook envelope id/type/created_at/organization_id/data. Events include checkout.completed, collection.succeeded/failed/underpaid, customer.subscription.created/updated/deleted, invoice.paid/payment_failed, refund.paid/failed, dispute.created/updated. checkout.completed may have no collected payment. Verify X-Bachs-Signature-V2 (t=timestamp,v1=hex possibly multiple v1) using HMAC-SHA256 of timestamp+'.'+unaltered raw body, constant-time comparison, strict timestamp parse and 300-second tolerance before parse. Legacy X-Bachs-Timestamp and X-Bachs-Signature supported only deliberately; reject malformed/contradictory headers. At-least-once, no ordering guarantee, 10-second acknowledgement; 5xx/408/429 retry, other4xx/3xx stop. Therefore durable store before2xx; no synchronous slow provider reconciliation before ACK. Documentation changes/read-only API schemas must be verified, not guessed.
