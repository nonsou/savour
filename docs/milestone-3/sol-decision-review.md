# Sol decision review — Milestone 3

Fable 5.1 reviewed the actual development code read-only. Accepted the additive architecture with the following binding corrections for Opus implementation.

1. Pin **15** pre-M3 snapshots from qa-snapshot-baseline.json, not twelve. Six applied migrations are sealed. Five proposed forward migrations are a suggestion; pick the smallest clean dependency order, with no edit to applied files.
2. Generated findings are append-only **per approved revision** (unique session/subject/criterion/revision), not updated in place across revisions. Retry of the same approval must deduplicate. Old finding evidence/action references remain truthful. Current critical attention must distinguish current generated evidence from historical findings, and manually raised findings remain active until explicitly resolved/withdrawn. Do not suppress a critical finding because one of several linked actions is closed while others remain active. Show the source revision and rule, including insufficient-data state for repeat rules. New generated evidence should not rewrite an earlier closed action or its finding. A repeat tag must use the versioned rule and compatible prior evidence, not text-label matches.
3. Overdue means every unfinished action, including ready_for_verification, until closed/cancelled. Due date is a local calendar day; it becomes overdue after that day ends in the workspace timezone. Notification dedupe keys must account for due_date and notification kind/local day without duplicates on retry; stale due reminders need live condition checks after due-date/state changes, not just membership checks. Lazy idempotent inbox sync is acceptable for development: explicitly disclose reminders are generated on inbox visit, with no background/email delivery claim.
4. Timestamp truth under contention: PostgreSQL now() is transaction-start time. Use clock_timestamp() after obtaining the session lock for action creation/update and approval timestamps so the after-approval appendix test is accurate. The session lock is the authoritative inclusion boundary; compare frozen action IDs/version timestamps, not timestamp guesses alone.
5. A race between progress and verify must start in a state where both competing operations are valid (e.g. ready -> return versus ready -> verify). Do not call an invalid-transition failure proof of concurrency/version correctness. Observe an actual lock wait with independent connections, then one winner plus stale loser.
6. Reviewer/Owner/Admin can progress for a reasoned documented override; Reviewer cannot verify own resolution. Owner/Admin self-verification needs a saved override reason. Assessor only own live assigned action; it must not gain full session/report access through an action. Viewer only approved scoped redacted report/analytics data. Guest denied every new surface. Inbox for Viewer/Guest may be refused consistently in RPC/navigation for M3, matching Fable's acceptance matrix. Notification read must recheck recipient and current entity-specific access; removed/reassigned/closed correction stale payloads and links fail closed. IDs/actor names/private contacts must be removed from viewer action snapshot/appendix/history and analytics; notes redaction limitations must remain visible.
7. Current action appendix is explicitly separate and server-dated for the viewed revision, including archived/reopened sessions. Never claim legacy approvals froze action data. Historical categories must use stamped snapshot IDs/names; legacy is Not recorded, never backfilled from today's directory. Location IDs may derive from immutable session scope but names remain historical. Subject history uses stable ID.
8. Filter options, table/CSV/PDF and attention links must share the same authorized dataset and arithmetic. All requested analysis views/filters must be present; don't stop at only a CSV or a mock dashboard. Group by template version, formula and criterion applicability. Expose denominator/coverage/missing/waiver/unknown/absence/sample exclusion and comparable n; show version boundaries. Separate provisional mode can't silently blend. No data is null, never zero. Attendance Off must not enter attendance flags. Critical/low/repeat triggers are settings frozen with template versions and unaffected by averages.
9. Read bundled Next 16.4 docs before editing, keep runtime publishable-key only, private definer/public invoker wrappers, explicit grants/RLS and FK indexes. Use Supabase CLI to create new migration filenames. No cloud/credentials/env reads, commits, pushes or deployments by Opus. Sol owns independent verification and remote operations.
